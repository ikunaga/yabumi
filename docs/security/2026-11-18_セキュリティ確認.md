## 問題がなかった主な点

- 作り直した関数はすべて search_path ''。anon はどれも実行できない。authenticated が実行できるのは利用者向けの関数と is_review_sns だけで、指紋・上限・claim_due_targets は service_role だけ。トリガーの関数は誰にも grant がない。前の定義から後退したところはない
- M1・R4 の直し: operator で止めた回し方は、利用者が再開・一時停止・削除・保存できない。posts.auto_created は利用者が付けられず、外せない
- 配信先を足すときは、status・sns の列を利用者が書けないので必ず pending から BEFORE INSERT のトリガーを通る。文・タグ・アカウント・引用・画像の付け外しと並びを変えると承認が外れ、送り直しと claim の両方で指紋を確かめる
- DB-L2（前回）: 上限は関数の中の定数になり、p_scope_owner は service_role だけ。前の形の関数は drop 済み
- フォーマットの画面: 使うサーバーの処理は変わっておらず、どれも projectId を確かめ、getClaims で本人を確かめてから RLS で読み書きする
- 自動の投稿の画面: 「開発の進み」は画面で隠すだけだが、サーバーの schema が段階 A の種類しか受け付けない。偽の AI は VERCEL_ENV か NODE_ENV=production で使えない
- 下書きに保存して読み込み直す: 保存の手順はモジュールの変数に置くだけで、端末に残さない。保存は savePost（本人確認つき）。step は zod で 1〜5 に限る
- 画像の欄: localStorage にはつくり方だけ（try/catch つき）。AI を呼ぶのは押したときだけで、サーバーの予約を通る。最初の枚数は 1 枚
- 送信の結果の読み直し: 20 秒ごと・30 回まで・見えているときだけで、読むのは DB だけ。外部の API は呼び直さない
- TikTok の Webhook は 64KB を超えれば読まずに 413。/tiktok-media の HEAD は引換券だけ。コメントの取り込みのログは分類のコードだけ。ジョブの合言葉は timingSafeEqual
- 新しい NEXT_PUBLIC_*・process.env・dangerouslySetInnerHTML・eval はない。Next.js は 16.4.6（16.4.5 で直った 7 件の advisory は yabumi に当たらないが、上げた）
