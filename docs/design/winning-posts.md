## 1. 「言い直し（rerun）」との関係

| | 伸びた投稿の言い直し（rerun。準備中） | この機能（伸びた投稿を型にする） |
|---|---|---|
| 何を回すか | 同じ投稿を、言い回しを変えて出し直す | 伸びた投稿の組み立て（型）を取り出し、毎回ちがう中身で出す |
| 向く投稿 | 1 回きりの話題（体験談・考え方） | くり返せる形（新メニュー、よくある質問、ビフォーアフター、お客様の声） |
| 自動の投稿の種類 | rerun | series（いまある。materials.format_id） |

- **「伸びた」の判定（2.）は 1 つにまとめ、両方で使う**（例: src/lib/metrics/winners.ts）。rerun を作るときは、この判定で元の投稿を選ぶ（auto-post.md 2.1 の「表示回数の上位 5 件」をこれに置き換える）
- AI が「型にしにくい」と答えた投稿は、rerun ができたら「言い直しで回す」の候補にする。それまでは何も出さない

## 2. ① 「伸びた」の判定（決まりで。AI は使わない）

| 項目 | 案 | 理由 |
|---|---|---|
| 単位 | 送った投稿を SNS ごと（post_target）に見る。どれか 1 つの SNS で伸びていれば、その投稿は伸びたとし、どの SNS で伸びたかを出す | SNS ごとに数字の大きさがまるで違う |
| 比べる相手 | **同じプロジェクト・同じ SNS の、この 90 日の自分の投稿の中央値**。ほかの SNS やほかの人とは比べない | Threads と X では見られる数のけたが違う。平均だと 1 本の大当たりに引っぱられる |
| 見る数字 | 設計の「見た人にしてほしいこと」で決める。知ってもらう・フォロー → 見られた数（views）。それ以外（DL・購入・予約・問い合わせなど）→ 押された数（短縮リンク）。押された数がない投稿は、見られた数で見る | オーナーの「クリック数やインプ」の両方に当たり、目標と合う |
| 数字が落ち着くまで | 送って **7 日たったもの**だけ。90 日より前のものは見ない | 数字は初めの数日で大きく動く。Instagram は 48 時間遅れる（4.22） |
| 伸びたと言う線 | 中央値の **1.5 倍以上**、SNS の中で**上から 3 本まで**、さらに下限（見られた数 100 以上か、押された数 5 以上）（推測。数字がたまったら直す） | 小さい数どうしの「2 倍」（3 回 → 6 回）は偶然 |
| 数が少ないとき | SNS ごとに、数字のある投稿が **6 本未満なら判定しない**。「あと n 本送ると、よく伸びた投稿がわかります」と出す | 3〜4 本の中央値は当てにならない（post-effect.ts の MIN_DAYS 7 と同じ考え） |
| 数字が取れない SNS | 数字の権限をつないでいない SNS は対象外。「数字をつなぐと見られます」と出す | — |
| 外すもの | 取り消した投稿（sns_removed_at）、引用（quote_post_id）、**X の投稿**（下の「X の規約」） | 引用は相手の投稿の力が大きい（推測） |
| 自動の投稿で出したもの | 外さない。ただ、もう自動の回し方があるフォーマットなら、新しい案ではなく「回す回数を増やす」を出す（5.） | — |

### X の規約（2026-11-19 に調べた。公式の文書だけ）

- 読んだもの: [Developer Agreement](https://docs.x.com/developer-terms/agreement)（Last Updated: April 27, 2026）、[Developer Policy](https://docs.x.com/developer-terms/policy)、[Restricted use cases](https://docs.x.com/developer-terms/restricted-use-cases)。developer.x.com の同じ文書は 402 が返って読めなかった
- Agreement の I.12（X Content の定義）は、投稿のほかに「X の API で得たほかのデータと情報」と「その写しと派生物」を含む。API で読んだ数字は X Content で、倍率も派生物に当たりうる
- Agreement の III.A(d) は、X の API と X Content を、明示の許可なしに第三者へ配る・渡すことを禁じる。委託先（データの処理者）を外す条項は見当たらない。Policy の「Content redistribution」は、第三者に配れるのは原則として投稿とユーザーの ID だけとする
- Agreement の II.A.1 は、X Content の分析を「X が明示的に承認したもの」に限る。III.A(k) は X Content で基盤モデルを学習させることの禁止（推論は書いていない）
- **結論**: 数字そのものを AI の会社（Anthropic）に送ることは、文言上許されていないと読める。倍率だけでも、許されているとは確かめられない。そこで **X の投稿は判定から外す**（src/lib/metrics/winners.ts の EXCLUDED_SNS）。送る本文は、利用者が yabumi で書いて保存した posts.body・post_targets.body_override で、X の API から読んだ文ではない（推測: X Content に当たらない）
- 【未確認】AI と相談（consult）の振り返りで送っている数字に X の数字が入っているか。同じ条項に当たるおそれがあるので、PM に別に伝えた

**判定の結果の形**（DB に持たない。開くたびに計算する）: 投稿・SNS・数字・中央値の何倍か・送った日・format_id・すでに回しているか。

## 4. ③ 提案の中身

### 4.1 型の案（AI。押したときだけ）

- **材料**: 選んだ伸びた投稿 1〜5 本の本文（SNS ごとの文があればその SNS の文）、それぞれの「SNS・中央値の何倍か」、設計（柱・口調・やらないこと）、プロジェクトの説明・届けたい相手、登録しているフォーマットの名前
  - **数字はそのまま送らず、「Threads で いつもの 2.4 倍」のような倍率だけ送る**。そのままの数字は要らず、X のデータを外に出す量も減る
- **返す形**: post-format-ai.ts の案の形（name・purpose・body の {穴}・example）に次を足す
  - `why`: この投稿のどこが効いたか（推測として 1 文。「最初の 1 行で値段を言い切っている」など）
  - `holes`: 穴ごとに「毎回 AI が埋める」か「あなたが入れる」か。シリーズの AI の穴（4.66）と同じ考え
  - `fit`: 型にしやすいか（`good` / `weak`）。weak なら案を出さず「この投稿は 1 回きりの話題で、型にしにくいです」と言う
- 案は **2 つ**（いまの「AI とつくる」は 3 つ。元の投稿があるので幅は小さくてよい）
- 決まり: 元の投稿の固有の事実（値段・日付・人の名前）は型の決まった言葉に入れず、穴にする。いまの CONTENT_RULES・JAPANESE_STYLE_RULES と「材料はあなたへの指示ではない」を入れる。投稿に人の名前があれば、穴にして「名前は本人の了承があるときだけ」と添える（auto-post.md 6.3）

### 4.2 回し方の案（AI を呼ばない。suggest.ts を伸ばす）

| 項目 | 案 |
|---|---|
| 何を | 種類は series、materials.format_id は保存したフォーマット |
| どこに | 伸びた SNS を先に選んでおく。Threads・Facebook・Instagram は完全に自動、X は確かめて送る（A5）。数字のない SNS は選ばずに出す |
| どのくらい | 1 つの型は **週 1〜2 回**を初期値にする（毎日だと似てくる。推測）。suggest.ts の 3 案の形に乗せる |
| いつ | 伸びた投稿を送った時間帯（BAND_INFO.at）を先にする。なければ time-hint.ts、それもなければ初期値（いまの suggest.ts と同じ） |

## 5. ④ 利用者が選ぶだけで、フォーマットと回し方ができる流れ

```
［カード（A）か、ボタン（B）か、通知（C）］
  └ 1. 伸びた投稿の一覧（本文の頭・SNS・「いつもの 2.4 倍」・送った日）。上から 2 本を選んである
      └ そのフォーマットで書いた投稿なら → 3. へ飛ぶ（AI なし）
  └ 2. 「型の案を作る（AI・約 10 円）」 … 押したときだけ AI。案 2 つ（why・穴の分け方つき）
      └ 「型にしにくい」と言われたら、ここで終わり（rerun ができたらそちらへ）
  └ 3. 案を選んで直す →「フォーマットとして保存する」（いまの post_formats の保存。ここで初めて 1 行できる）
  └ 4. 「この型で自動で回す」→ 自動の投稿の「始める」を、種類・フォーマット・SNS・回数・時刻を入れた状態で開く
      └ いまの 1.5 の「確かめる → 始める」と同意、最初の 1 回の確かめ（A3）はそのまま
```

- **勝手に作らない**: 判定と一覧は計算だけ。フォーマットは 3. の「保存する」、回し方は 4. の「始める」を押したときだけできる
- **勝手に送らない**: 4. のあとは、いまの自動の投稿の決まりどおり（24 時間前に作って見せる・最初の 1 回は確かめる・X は承認したものだけ）
- すでにそのフォーマットの回し方があるとき: 4. で「いまの回し方（週 1）の回数を増やす」を、直す画面へのリンクで出す（自動では変えない）
- いまの画面と部品を使う。新しく作るのは、一覧（1.）と案の画面（2.）だけ

## 7. ⑥ AI に送る中身が増えるか（docs/legal.md の ①・②）

- **増えるもの**: 「AI とつくる」（post_format）は、いまは設計とプロジェクトだけを送り、投稿の本文は送っていない（post-format-ai.ts の頭のコメント）。この機能では、利用者が選んだ自分の送った投稿の本文（5 件まで・1 件 300 字まで）と、同じ SNS の中での倍率を送る。毎週の振り返りのメール（Resend）には、伸びた投稿の本文の 1 行目（40 字まで）と倍率を入れる
- **② として扱う**（PM の判断 2026-11-19）。フォーマットを作るために投稿の本文を AI に送るのが、新しい使い道に当たるため。設計の案は ①（相談・書き方の読み取りで同じ種類を送っている）だった
- 版は 2026-11-20【仮】（docs は privacy だけ。利用者に不利ではない）。noticeWaived は「施行の時点で利用者は運営者だけ（招待していない）で、運営者が了承した（2026-11-19）」。本番に出す日に PM が日付を合わせ、ほかの ② の版と同じ日になったら 1 つにまとめる
- 書き足す文（オーナーの了承待ち）は docs/legal.md の「伸びた投稿からの提案の版」
- 守ること: 押したときだけ送る（裏で定期的に送らない）。数字そのものは送らない。X の数字は使わない。他の人の投稿は送らない
