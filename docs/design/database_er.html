1. 全体像

区分ごとの箱と、区分どうしのつながり。箱を押すと区分の図へ移る。

2. プロジェクトと SNS

プロジェクト（宣伝するもの）を中心に、つないだ SNS アカウント・アカウント設計・行き先などがぶら下がる。SNS アカウントは利用者のもので、どのプロジェクトで使うかを結びつきの表で持つ。

3. 投稿とフォーマット

投稿は本文と予定の日時を持ち、SNS ごとの送り先（送信の状態）に分かれる。画像と動画は投稿かネタ帳のメモに付く。投稿のフォーマットは繰り返し出す投稿の型で、シリーズの記録に回ごとの答えを残す。

4. 自動の投稿

自動の回し方（設定）から、回（1 回ずつ）が作られ、回が投稿を作る。材料のフォーマット・行き先・メモ・予定は、回し方の材料の選び方（materials）と回の使った材料（material_ref）の jsonb の中で ID を持つだけで、外部キーではない。

5. 数字とコメント

送った投稿の数字とコメントは送り先に、アカウントの数字は SNS アカウントに、ストアの数字はプロジェクトにぶら下がる。

6. 短縮リンク

短縮リンクはプロジェクトにぶら下がり、投稿の本文に置いたものは送り先を指す。クリックはだれかわからないように、日替わりの塩で伏せて保存する。

7. 目標と伴走

目標（KGI）に中間の目標と KPI がぶら下がり、ロードマップのやることは目標とプロジェクトにつながる。通知の設定と宛先は利用者ごと。

8. AI・費用・学び

AI との会話と使った量・費用、SNS の API と X の検索の費用は、月の上限の判定に使う。学びの記録は利用者ごと。

9. 規約と運営

規約への同意と、規約の変更の知らせを送った記録。招待の申し込みと運営者への知らせは、サーバーだけが扱う。

10. 読むときの注意点

利用者（auth.users）は図に出していない

ほとんどの表は持ち主（owner_id、表によっては user_id）で Supabase の認証の利用者（auth.users）を指す。外部キーの制約はあるが、型のファイルには出ないため、各図では省いた。退会すると、ほとんどの行は一緒に消える。

jsonb の中で指している参照は、データベースでは確かめない

自動の回し方の材料の選び方（materials）と回の使った材料（material_ref）は、フォーマット・行き先・メモ・予定の ID を jsonb の中に持つ。投稿のフォーマットの投稿の柱は、アカウント設計の中の柱を名前で指す。消しても参照は残るので、読む側で無いものとして扱う。

状態と結果はサーバーが決める

目標・自動の回・送り先の状態など、利用者が書き換えてはいけない列は、列の権限（grant）で書けないようにし、書き込みは関数とサーバーだけにしている。RLS は行だけを絞る。

消す期限がある表がある

SNS のコメントは 30 日、通知を送った記録は 90 日、自動の回と承認の記録は 13 か月、お知らせ・季節の予定は日付から 1 年で消す。費用の記録（AI・SNS の API・X の検索）は、退会しても持ち主を空にして残すものがある。
