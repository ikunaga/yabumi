## 問題がなかった主な点

- 下書きの一覧と「下書き n 件」は、利用者の権限（RLS）で読み、1 つの関数で数える。他人の projectId では 0 件
- post_format_rounds は RLS が有効で本人だけ。insert は自分のフォーマットだけ・post_id は空、update は post_id だけで、まだ結びついていない記録を自分の投稿にだけ結べる。上限 300／3,000 は lock の中で数える
- シリーズの AI は reserve_ai_usage('post_format_round') を通り、1 日 20 回と下限を関数の中で固定。system は固定の文で、利用者の指示・答え・貼った回・希望は user のメッセージにタグで囲み、無害化して入れる
- posts.format_id は posts_check_format で、同じ持ち主・同じプロジェクトのフォーマットだけを通す
- post_targets は、authenticated が update できる列が 5 列だけで、pending でない行は変えられない
- 画像の元は、利用者の権限で読んだ行の分だけ admin で署名つき URL を作る。他人の画像を元にすることも、他人のファイルを消すこともできない。media_files は利用者から insert・update・delete を revoke
- cleanup_media_candidates と issue_media_upload_ticket は、前の定義との違いが source_of の条件だけ。service_role だけが呼べ、search_path は ''
- 書きかけの控え（localStorage）には秘密も他人の情報も入らない。戻すときは持ち主を確かめる
- HARM は system に固定の文を足しただけで、AI に送る利用者のデータは増えていない
- anon が実行できる public の関数はない。RLS が無効な public の表もない。新しいコードに dangerouslySetInnerHTML・console.log・新しい NEXT_PUBLIC_* はない
