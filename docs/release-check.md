## 1. 通しの確認（デプロイの前に毎回）

画面を変えた機能は、「利用者がやりたいこと」の単位で、初めて使う人役の AI に通しで操作させてから出す。

- 例:「連想映画クイズを自動で回す」「予約した投稿を見て、1 日だけ飛ばす」「投稿を 1 本つくって予約する」
- やり方
  1. 担当が、その流れの手順ごとのスクショを撮る（SP・ダークを基本。下の 2. の状態も）
  2. ja-copy-reviewer（.claude/agents/ja-copy-reviewer.md）に、スクショと「やりたいこと」を渡す。手順ごとに「ここで何をすると思うか」「何が起きると思うか」「迷ったところ」を答えさせる
  3. ✗ が 1 つでも残っていたら出さない。△ は書き直すか、残す理由を PM に送る
- 担当は、取り込みを頼むときに、確認役の結果（✗・△・○ の数と、書き直した文）とスクショの場所を必ず付ける。付いていなければ、PM は取り込まない

## 2. 状態ごとのスクショ

画面を変えたら、その画面にある状態をすべて撮る。撮った状態の一覧を、取り込みを頼むときに付ける。

| 画面 | 撮る状態 |
|---|---|
| 投稿（投稿をつくる・投稿の画面） | 新しく作る・下書き・予約済み・確認待ち・送信中・投稿済み・失敗 |
| 自動の投稿 | 作る前・動いている・止めている・運営者が止めている・確認待ちあり・失敗あり |
| フォーマット | 0 個・ふつう・シリーズ・画像の設定あり |
| 一覧の画面 | 0 件・1 件・たくさん |

その画面にない状態は「なし」と書く。

## 3. よく使う画面の許す一覧を、先に空にする

- 対象: 自動の投稿（ウィザード・一覧・設定・確認待ち・予約済みの投稿）、投稿をつくる、概要
- この 3 つは、tests/ui-wording.allow.json の当たりを 0 にするまで、新しい機能を足さない（直しは除く）
- 言い換えの表（docs/design/ui-words.md）にある言葉は、許す一覧にあっても、画面全体で一度に直す（「穴」「直す」「確かめ」「回」と同じやり方）

## 4. オーナーに見てもらう前に、PM が見る

- 「本番で見てほしいところ」を伝える前に、PM がその画面のスクショ（担当のもの、または本番の画面）を自分で読む
- 1. の確認役の結果も読む。気になる点があれば、先に直してから伝える
- オーナーへの報告には、PM が見た画面と、見ていない画面を分けて書く
