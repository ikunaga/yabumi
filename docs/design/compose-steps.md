# 投稿をつくるを、1 ステップずつ進める画面にする（設計。feat/compose-steps）

オーナーの Notion の項目「投稿作業が 1 ページに色々あって操作順などわかりづらい。step ごとに 1 操作ずつ進める UI にする」。PM の依頼（2026-11-10）。この文書は設計だけで、実装は PM の了承のあとに段階 A から始める。

## 0. いまの作り（調べた結果）

- 画面は src/components/posts/post-composer.tsx（1,371 行）の 1 つの部品。新しい投稿は /projects/[id]/compose、保存した投稿は /projects/[id]/posts/[postId] で、どちらも同じ部品を使う
- PC は 2 列（左: 本文から送るまで、右: SNS ごとの見え方と文面のタブ）。スマホは 1 列で、右の列は左の列のずっと下に来る
- 左の列に 1 つのカードで、本文 → AI で整える → 書いたのは誰 → 送り先 → 注意 → 画像 → 短縮リンク → 日時 → 予約・今すぐ・下書き、が縦に並ぶ。その下に「書くときの手伝い」（設計を見返す・送る前に AI に見てもらう）
- 送り先は、つないだ SNS（ロードマップのやることから開いたときは、その SNS）が初めから選ばれている
- 書きかけ（端末に残す控え。src/lib/form-draft.ts）と、下書きに保存（DB）の 2 つで、途中で閉じても戻れる

## 2. ステップの区切り

1 画面で決めることを 1 つにする。進みは「1/5」と名前で出し、どのステップにも戻れる。

| ステップ | 決めること | 中身 | 次へ進める条件 | 飛ばせるか |
|---|---|---|---|---|
| ① 書く | 何を伝えるか | 本文（自分で書く・AI で整える・ネタ帳から・フォーマットから）、書いたのは誰 | 本文が空でない | 飛ばせない |
| ② 送り先 | どこに出すか | SNS を選ぶ、SNS ごとの見え方と文面・タイトル | SNS を 1 つ以上選んだ（下書きだけならあとで選んでもよいので、「あとで選ぶ」で次へも進める） | 飛ばせない（「あとで選ぶ」はある） |
| ③ 画像 | 画像を添えるか | 選ぶ・つくる・縦横・調整・説明文 | なし | 「画像なしで次へ」 |
| ④ リンク | 行き先へ案内するか | 行き先の URL・短縮リンク・Instagram のプロフィールのリンク・X の URL の費用 | なし | 「リンクなしで次へ」 |
| ⑤ 送る | いつ出すか | まとめ（①〜④ の短い要約と「直す」）、AI の見直し、日時、予約・今すぐ・下書き | 送る前の確かめ（いまの blocker）が通る | ― |

- 決めかねる点（PM に判断してほしい）: ① の「AI で投稿に整える」は、送り先の SNS ごとに文面を作る（字数が SNS ごとに違うため）。送り先は初めから選ばれているので、① ではそれを使い、「X・Threads 向けに整えます（送り先は次のステップで変えられます）」と 1 行で出す。② で SNS を足したら、足した SNS は共通の本文で送る（いまと同じ）。順番を「② 送り先 → ① 書く」に入れ替える案もあるが、オーナーの言う「何を書くか」から始めるほうが自然なので、この順をすすめる
- ① の字数は、選ばれている SNS のうち上限のいちばん小さい SNS で数える（いまと同じ）
- ④ は送り先に Instagram・X がないとき、注意が 1 つも出ないので、中身は行き先の URL と短縮リンクだけになる
- ⑤ のまとめでは、ステップごとに問題を印で出す（例:「② X の文面が 12 字多い → 直す」「③ Instagram に合わない縦横の画像が 1 枚 → 直す」）。「直す」でそのステップに飛ぶ。送れない理由（いまの blocker）は、どのステップの問題かを添えて出す

## 3. 画面の作り

### ステップの進み

- PC: 上に 5 つのステップを横に並べる（番号・名前・済みの印 ✓・問題の印 ●）。どれでも押して移れる
- スマホ: 上に「2/5 送り先」と点 5 つ。点を押すと、ステップの一覧が開いて移れる
- 下の帯（スマホは画面の下に固定。下のタブの上）に「← 戻る」「次へ（画像）→」。⑤ では「次へ」の代わりに「予約する」
- 「下書きに保存する」は、どのステップでも上の帯の右に小さく置く（途中でやめたくなっても、いまどこにいても保存できる）。リセットも上の帯の「…」の中

### プレビュー（見え方）の置き場所

- PC: 右の列に、どのステップでも SNS ごとの見え方を出す（いまと同じタブ）。① で本文を書くと、右ですぐ見え方が変わる。② では右の列で SNS ごとの文面も直せる（いまと同じ）
- スマホ: ② と ⑤ では、見え方を中に出す（② は SNS のタブ、⑤ はまとめの下に選んだ SNS を順に）。①・③・④ では、下の帯の上に「見え方を見る」を畳んで置き、開くと下から出る（閉じると元の場所）

## 4. 開き方・戻り方

| 開き方 | 始めるステップ |
|---|---|
| 新しい投稿（/compose、ロードマップのやること・カレンダーの日付から） | ① 書く |
| 保存した下書き（ネタから下書きにしたもの・下書きに保存したもの） | ⑤ 送る（まとめから、直したいステップに飛ぶ）。本文が空なら ① |
| 一部だけ送った投稿 | ⑤ 送る（残りの SNS を予約・送信） |
| すべて送った投稿 | ステップは出さない（6.） |
| 書きかけの帯で「戻す」 | 控えたときのステップ |

- いまのステップは URL（?step=2）に持つ。ステップを移るたびに履歴に足すので、スマホのブラウザの「戻る」で前のステップに戻れる。読み込み直しても同じステップ
- 書きかけ（端末の控え）の仕組みは変えない。控えに、いまのステップを 1 つ足す（戻すと同じステップから）。控えが残る・消える決まり（draftStep・usableFormDraft）は変えない
- 下書きに保存は、どのステップでも押せる（いまと同じ中身を保存する）。保存したあとは、そのステップのまま
- 保存・送信を押している間は、いまと同じように画面全体を止める（inert）

## 5. 「1 ページで全部見る」に切り替えられるようにするか

作らないことをすすめる。

- オーナーの「1 操作ずつ」は、迷わないことが目的。2 つの見せ方があると、どちらで何をするかをまた考えることになる
- 画面が 2 通りになると、直すたびに両方を確かめる手間が倍になる（テスト・スクショ）
- 全体を見たいときの代わりは 2 つある。⑤ のまとめ（①〜④ の要約と「直す」）と、上の進み（どのステップにも 1 回で移れる）。PC では右の列の見え方も、どのステップでもずっと見える
- 慣れた人が速く進めるよう、③・④ は「なしで次へ」で 1 回で飛ばせ、保存した下書きは ⑤ から始まる
- 使ってみて、オーナーが「全部見たい」と思ったら、そのときに足す（⑤ のまとめを広げる形なら、作り直しは小さい）

## 6. 送った投稿の画面

すべて送った投稿は、ステップに分けない（決めることが残っていない）。いまの見出し・送った結果・数字（post-numbers-band）に、送った文面と見え方を読むだけで並べる。ほかの SNS にも送るときは「ほかの SNS にも送る」で ② から始める（いまはチップで選ぶ）。

## 7. 実装担当2 の「投稿のフォーマット」との分け方（2026-11-10 にすり合わせた）

- フォーマットを選ぶ欄は ① 書く の先頭（本文の欄の上）。私が ① の部品（ComposeStepWrite）に差し込み口を空け、中身（チップ・穴の欄・本文に入れる）は実装担当2 が入れる（実装担当2 の docs/design/post-formats.md。中身は src/components/posts/post-format-picker.tsx）
- 並ぶのは「なし」と登録したフォーマットのチップ。選ぶと穴の小さな欄が並ぶ。フォーマットをつくる「フォーマットを管理」も、① の中に畳んで置く（例から足す・手で書く・AI とつくる。絵の説明のフォーマットと同じ作り）
- 「本文に入れる」は PostComposer の本文の書き換えとして、いまの setBody と markTyped（書きかけを残す印）を通す（書きかけの控えとリセットにも乗る）
- 「AI で投稿に整える」と「整え方を選ぶ」は ① の本文のすぐ下のまま。フォーマットは TidyDraftPanel の props で渡す
- 先に main に入ったほうに、あとの人が合わせる。実装担当2 が先なら、いまの画面の本文の上に置いてもらい、私が切り出すときに ① の先頭へ移す

## 8. 今の機能を壊さない移し方（段階）

状態（本文・送り先・SNS ごとの文面・画像・短縮リンク・日時・保存と送信）は、いまの PostComposer に 1 つのまま残す。見せ方だけをステップに分けるので、保存・送信・書きかけ・リセットの動きは変わらない。

| 段階 | すること | 画面の変わり方 | 確かめ |
|---|---|---|---|
| A. 切り出し | post-composer.tsx の JSX を、ステップごとの部品（ComposeStepWrite・ComposeStepTargets・ComposeStepImages・ComposeStepLinks・ComposeStepSend）と右の列（ComposePreview）に切り出す。props で状態と操作を渡すだけで、並びも動きも変えない | 変わらない | テスト全部、前と後のスクショが同じ（PC・スマホ・明暗） |
| B. ステップ | 進み（上）・下の帯（戻る・次へ）・?step・⑤ のまとめ・開き方（4.）を足し、1 画面に 1 ステップだけ出す。スマホの「見え方を見る」 | ステップになる | テスト、ステップごとのスクショ、開き方ごとの確かめ（新しい・下書き・一部送った・すべて送った・書きかけを戻す・ブラウザの戻る） |
| C. 仕上げ | ⑤ のまとめの問題の印と「直す」、送れない理由のステップの添え書き、スマホの鍵盤と下の帯、送った投稿の読むだけの画面と「ほかの SNS にも送る」 | 細かく変わる | 同上 |

- A は単独で main に入れられる（見た目が同じなので、ほかの人の変更とぶつかったときに直しやすい）。B と C は続けて入れる

### 段階 B で作ったもの・設計から変えたところ（2026-11-10）

- ステップの決まりは src/lib/posts/compose-steps.ts（startStep・parseStep・canGoNext・problemsByStep・stepMarks・fieldErrorStep）。テストは tests/compose-steps.test.ts
- いまのステップは URL の ?step（history.pushState。ブラウザの戻るで前のステップへ）。保存で欄のエラーが返ったら、その欄のステップへ移る
- ステップを移っても部品は外さず、ほかのステップは hidden で隠す（AI で整えた案・画像をつくる画面・投稿のフォーマットの穴・AI の見直しの結果など、部品の中の値を消さない。2026-11-10 に PM の了承）
- リセットは「…」の中ではなく、上の帯の「下書きに保存する」の横に小さく置いた（1 つしかないので、畳む意味がない）。「下書きに保存する」は ①〜④ で上の帯に、⑤ では中のボタンだけ
- 上の帯には、予約の日時・保存のエラー・書きかけの帯も置いた（どのステップで保存しても見える）
- ① で送り先が空のときは、「AI で投稿に整える」の横に「送り先を選ぶ →」（② へ）を出す
- スマホの下の帯は、下のタブの真上に留める。見えている高さが画面より 150px 以上減ったとき（鍵盤が開いたとき）は隠す
- 見え方: 横に並ぶ幅（64rem 以上）は右の列にどのステップでも。狭い幅は ② と ⑤ の中に出し、ほかのステップでは「見え方を見る」に畳む（どの幅でも 1 つだけ描く）
- すべて送った投稿は、段階 C で読むだけの画面にするまで、いままでの 1 ページのまま
- 段階ごとに main に入れ、実装担当2 のフォーマットとは 7. のとおり合わせる

## 9. テストの方針

- ステップの決まりを、画面から切り離した関数にする（src/lib/posts/compose-steps.ts）。テストはここを中心にする
  - stepStatus: ステップごとに「済み・問題あり・まだ」を、いまの状態（本文・送り先・字数の確かめ・画像の確かめ・blocker）から決める
  - canGoNext: 次へ進める条件（2. の表）
  - startStep: 開き方ごとの始めるステップ（4. の表）
  - problemsByStep: いまの blocker と SNS ごとの確かめを、どのステップの問題かに分ける（⑤ のまとめと「直す」の行き先）
  - parseStep: ?step の値（範囲の外・数でないものは始めるステップに）
- 書きかけ: 控えにステップを足しても、いまのテスト（tests/form-draft.test.ts）が通り、ステップつきの控えを戻すと同じステップになること
- 保存と送信のテスト（結合テスト）は、状態を変えないので、そのまま通ること
- 画面: 段階ごとに PC（1440×900）とスマホ（390×844）、明暗でスクショを撮る。B では、ステップごと・開き方ごとに撮る。本物の SNS には送らず、AI はいまと同じく呼ばない（seed したデータ）

## 10. 決めてほしいこと

1. ステップの区切り（5 つ。③ 画像と ④ リンクを分けるか、1 つにまとめて 4 つにするか）。すすめは 5 つ（④ に Instagram のプロフィールのリンクと X の URL の費用が入り、③ と混ぜると 1 画面の決めることが 2 つになるため）
2. 順番（① 書く → ② 送り先）でよいか。① の「AI で投稿に整える」は、初めから選ばれている送り先で整える（2.）
3. 保存した下書きを ⑤ 送る（まとめ）から開いてよいか
4. 「1 ページで全部見る」は作らない（5.）でよいか
5. 段階 A（見た目を変えない切り出し）を先に main に入れてよいか
