# シリーズ投稿（フォーマットの一部を AI が毎回埋める）

オーナーの Notion の Next Cycle の項目「定型のフォーマットを作って、一部だけAIに内容を変えてシリーズ投稿ができるようにする」（2026-11-13、PM の依頼・了承）。投稿のフォーマット（docs/design/post-formats.md、docs/architecture.md の 4.56）を土台にする。

## 0. 例と考え方

オーナーの例は「連想映画クイズ」。型（「連想映画クイズ／{キーワード}／この 5 つから連想する映画は？答えはリプで」）は毎回同じで、映画とキーワードだけが変わる。

- いまのフォーマットは、穴を利用者が埋める。これに「AI が埋める空欄」と、本文に出さない「答え」を足し、AI が前の回と重ならない「次の回」を出す
- 答え（映画の名前）は本文に出ないので、出した投稿の本文からは重なりを判定できない。回ごとの答えと穴の言葉を「シリーズの記録」として別に持つ

## 1. フォーマットの設定（series）

- 編集の欄で、穴ごとに「自分で埋める／AI が埋める」を選び、AI が埋める穴には短い指示（60 字まで）を書く。例「上の映画を連想できる言葉を 5 つ。・でつなぐ」
- 本文に出さない「答え」を 1 つ持てる（Q2。名前 12 字まで・指示 60 字まで）。例: 名前「映画」、指示「だれでも知っている映画を 1 つ」。AI は答えを先に決めて、それに合う穴を埋める
- 「答えを持つ」を選んで名前を空にしたときは、名前を「答え」にする（前は黙って答えなしになった。2026-11-13 PMO2 の 3 回目の n1）。答えを持たない型でも、AI は何についての回か（作品やものの名前）が決まるなら答えに書き、案のカード・答えの欄・これまでの回に出す（本文には入れない）。答えのない型の重なりは、穴の言葉の組み合わせに加え、答えが同じ案も捨てる
- 型の文の記法（{穴}）は変えない（{AI:…} のような記法は書き間違えやすく、指示を書く場所もないため）
- 持ち方: post_formats.series（jsonb）`{"answer": {"name", "instruction"} | null, "slots": {"穴の名前": "指示"}}`。AI の穴は 8 つまで。~~型の文にない穴の指示は、保存のときに捨てる（アプリ）~~ → 2026-11-20 から、型の文にない AI の空欄は「画像だけで使う空欄」として残す（1.1）。DB の check は形・キー・字数
- AI の穴が 1 つもないフォーマットは、いままでどおり（シリーズにならない）

### 1.1 画像だけで使う空欄（2026-11-20 オーナーの指示「全部、実現できるように修正して」）

- 目的: 連想映画クイズで、キーワードを本文に出さず、画像（絵の説明）だけに使う。本文は決まった文のまま
- 持ち方: series.slots の中で、**型の文にない名前の AI の空欄**を「画像だけで使う空欄」とする（新しいキーは作らない）。DB の check（slots は 8 つまで・名前 12 字・指示 60 字）はそのまま使えるので、マイグレーションは要らない。AI の空欄と合わせて 8 つまで
  - 名前は 12 字まで・「{」「}」と改行なし（okSlotName）。答えの名前と同じものは、保存のときに捨てる（答えと区別できないため）
  - 本文から空欄 {x} を消すと、AI が埋める設定だった x は画像だけで使う空欄に移る（編集の欄の「画像だけで使う空欄」に出るので、要らなければ「外す」）
- 編集の欄: 「毎回 AI に変えてもらう」の下に「画像だけで使う空欄」（名前を書いて「足す」・AI への指示・「外す」）。本文に空欄がなくても出す。絵の説明・見出しのチップにも出る（imageSlotNames）
- 次の回の案（AI）: 指示に「AI が埋める空欄 {x}（本文には出さず、画像の絵の説明だけに使う）」と書き、ほかの空欄と同じく埋めさせる。埋めていない案は捨てる。重なりの判定（答えがないときの空欄の言葉の組み合わせ）にも入る
- 記録（post_format_rounds.values）: 画像だけで使う空欄の言葉も残す（cleanRoundValues に series を渡す）。自動の回はもとから案の値をそのまま残す
- 投稿をつくる: 空欄の欄に「画像だけで使う・本文には入りません」として出し、編集できる。「本文に入れる」では本文に入らない（fillFormat は型の文の空欄だけ）。画像をつくるとき（そのまま使う・AI が絵の説明を書く）に使う。サーバーで絵の説明を埋めるとき（runFormatPhotoScene）も、型の文の空欄と画像だけで使う空欄の言葉だけを受け取る
- 自動の回・見本: 案の値に入るので、画像（src/lib/auto-post/image.ts）の絵の説明・見出しに入る
- 本文が毎回同じ型（型の文に AI の空欄がないシリーズ。fixedBodySeries）（2026-11-20 PM の判断）
  - 自動の投稿の送る前の確かめ「前の投稿と似ています（similar）」は、本文が毎回同じなので毎回止まっていた。この型では本文で見ない（plainIssues の skipSimilar）。重なりは、次の回の案を選ぶときに、答え（答えがなければ空欄の言葉の組み合わせ。画像だけで使う空欄を含む）で見ている（normalizeRoundProposals）
  - X は選べない。ウィザードで X の印を押せなくし、その場に「X は同じ文の投稿を続けて送れないため、本文が毎回同じフォーマットでは選べません。」を出す。保存（saveAutoPlan）でも断る。あとからフォーマットを固定の本文に変えたときは、自動の回で材料なし（cannot_write）にする
    - 出どころ: X の自動化の決まり（https://help.x.com/en/rules-and-policies/x-automation）は、1 つのアカウントで重複した・ほぼ同じ投稿をすることを禁じている。X の API は、同じ文の投稿を「duplicate content」で断る（v2 は 403）。2026-11-20 に確かめた。help.x.com はこの環境から 403 で本文を直接読めず、検索結果の要約で文面を確かめた。API の断り方は、X の API の文書（https://docs.x.com/x-api/posts/create-post）には書いていない。外部の連携サービスの文書の記載で確かめた
  - Threads・Instagram は選べるまま。Threads の API の文書（https://developers.facebook.com/docs/threads/overview）と Instagram のコンテンツ公開の文書（https://developers.facebook.com/docs/instagram-platform/content-publishing）には、同じ文の投稿の決まりはない（上限は本数だけ）。Meta のスパムの決まり（https://transparency.meta.com/policies/community-standards/spam/）は、とても高い頻度の投稿を禁じ、同じ中身のくり返しをスパムの目安の 1 つに挙げている。自動の投稿は 1 日に SNS ごと 2 本までで、画像は毎回違うので、当たらないと判断した
  - フォーマットの編集の欄に「● 本文に AI が埋める空欄がないので、本文は毎回同じになります。X は同じ文の投稿を続けて送れないため、自動の投稿では X を選べません。」を出す
- 画像だけで使う空欄を、絵の説明でも見出しでも使っていないときは、編集の欄に注意を 1 行出す（保存は断らない）
- 法務: 預かる情報（シリーズの設定・回ごとの空欄に入れた言葉）・送り先（Anthropic・Google）・使い道は変わらない。docs/legal.md に記録

## 2. シリーズの記録（post_format_rounds）

- 新しい表。id・format_id（フォーマットを消すと消える）・owner_id・post_id（任意。投稿を消すと null）・answer（100 字まで）・values（穴の言葉。jsonb、穴 16 個・1 つ 200 字まで）・source（ai: AI の案を使った / pasted: これまでの回を貼った / hand: 自分で埋めて本文に入れた）・created_at
- RLS は本人だけ。insert は自分のフォーマットだけ（post_id は空）。update は post_id だけで、まだ結びついていない記録を自分の投稿に結びつけるときだけ（一度結びつけたら付け替えない。投稿を消すと空に戻る）
- 1 つのフォーマットに 300 回まで、1 人の合計で 3,000 回まで（トリガー。フォーマットの行を押さえ、利用者ごとの advisory lock の中で数える。同時に足しても超えない）
- 記録を付けるとき（Q1）: AI の案を選んで「本文に入れる」を押したとき（AI の穴があるフォーマットで、自分で埋めて入れたときも hand として付ける。次の回の案で重ならないように）
- リセット・「保存した内容に戻す」で本文から外したとき（「AI で投稿に整える」の「元に戻す」は整える前の本文に戻すだけで、フォーマットで入れた中身は残るので、記録は消さない）: **その画面で付けた記録で、まだ投稿に結びついていないもの（post_id が空）は消す**。残すと、使っていない回が次の回の案から外れてしまうため。投稿を保存したら、その画面で付けた記録をその投稿に結びつける（以後は消さない。投稿を消しても記録は残る＝もう出した回として扱う）
- 画面を閉じた・保存しなかったときに残った記録は、フォーマットの画面（/projects/[id]/formats。2026-11-18 から。前は投稿をつくるの「フォーマットを管理」）の「これまでの回」に出し、利用者が消せる（自動では消さない。重ならない向きに倒す）
- **シリーズにして保存したとき（AI が埋める穴が 0 から 1 以上になったとき。新しく作ったときも）**、その場で「これまでに出した回はありますか？　貼ると、次の回の案と重なりません」と出し、そのフォーマットの「これまでの回」を開いて「これまでの回を貼る」をすぐ使えるようにする（2026-11-18 PM の依頼。オーナーの連想映画クイズで、シリーズにする前に出したバック・トゥ・ザ・フューチャーを AI がもう一度案に出した。記録に入っていない回は避けられず、「これまでの回」が奥に畳まれていて気づけなかったため）。貼る処理は今のもの（pasteFormatRounds、source = pasted）。過去の投稿の本文を AI に渡す案は今回はやらない
- 「これまでの回を貼る」: yabumi の外で出した回の答えを 1 行に 1 つ貼る。1 回に 100 行まで（300 回の上限と合わせ、残りが少なければ残りまで）。同じ答え（大文字小文字・空白をそろえて比べる）は足さない

## 3. 次の回の案（AI）

- ① でフォーマットを選ぶと、AI の穴がある型には「AI に次の回を出してもらう」を出す。案は 3 つ。それぞれ、答え（「答え: 〇〇（本文には出ません）」）・穴の言葉・「確かめてほしいところ」（1〜3 個）
- 「これを使う」で穴の欄に入る（自分で埋める穴はいままでどおり）。直してから「本文に入れる」。記録はここで付ける
- AI に渡すもの: プロジェクト・口調・柱（投稿のフォーマットの案と同じ）、フォーマットの型の文・AI の穴と答えの指示・自分で埋める穴の名前、もう出した回（直近 100 回の答えと穴の言葉。1 回 300 字までに切る）、利用者の希望（任意、100 字）
- 重なりを捨てる: 答えが、記録（全件。300 回まで）と同じ案、案どうしで同じ案は捨てる（大文字小文字・空白・中黒の違いをそろえて比べる）。捨てて 0 になれば「うまく案をつくれませんでした」
- AI の上限: 用途 post_format_round。1 人 1 日 20 回（reserve_ai_usage の lock の中で数える）。予約の下限 0.1 ドル。AI_MAX_TOKENS 2,500
- 費用の見込み: 入力 3〜7 千トークン（指示 2 千＋設計 1 千＋もう出した回 100 回で 1〜4 千）、出力 0.6〜1 千。Opus 5.5 で 1 回 $0.03〜0.05（4〜8 円）

## 4. 材料にない事実を書かない決まり（content-rules）との関係

- AI が埋める穴と答えだけ、決まりの例外にする。範囲は「利用者がフォーマットで指示した、広く知られた作品・ものごとについての一般的な事実（映画の題名・中に出てくる要素など）」。利用者の商売・お店・商品・人についての事実は、いままでどおり書かせない
- 確かでない要素は使わない。案ごとに「確かめてほしいところ」を短く書かせる（例「時計台の場面は第 1 作にあります」）。画面の案の上に「AI は作品の中身を間違えることがあります。出す前に確かめてください」
- ネットで調べる機能は使わない（費用と出どころを増やさない）。送る前の AI のチェックはいまのまま本文だけを見る

## 5. 法務（Q3）
