## 問題がなかった主な点

- post_formats・photo_prompt_templates は RLS を有効にし、本人だけ。insert でプロジェクトが本人のものか確かめ、update の列の grant に project_id・owner_id がない（付け替えられない）。上限 20／100 はプロジェクトの行を押さえ、利用者ごとの advisory lock の中で数える
- project_limit は security definer・search_path ''・revoke all。上限 10 は関数の中で固定
- post_target_text は service_role だけが実行できる。save_post は security invoker のまま、送ったあとの配信先を書き換えない。claim_due_targets は文の組み立て以外は前と同じ
- project_step_flags（作り直し 2 回）は security invoker のまま。中で使う関数も invoker で、他人のプロジェクトの数は読めない
- reserve_ai_usage の voice_memo・post_format の回数は、予約と同じ lock の中で ai_usage（本人は消せない）を数え、上限は関数の中で固定
- anon が実行できる public の関数はない。RLS が無効な public の表もない
- 投稿のフォーマット・AI とつくる・AI で整える・AI のチェックは、利用者の権限で読み、利用者の入力は user のメッセージにタグで囲んで入れる。system はどれも固定の文
- restoreDraftImages は利用者の権限で読み、「この投稿の画像」か「どこにも添えていない 20 時間以内の画像」に絞ってから、その分だけ admin で署名つき URL を作る。他人の id を混ぜても返らない（結合テストあり）
- 「X は手で投稿する」の印（failed ＋ 決まった文）は、サーバーしか書けない（post_targets の update の grant に error_message はない）。判定は isXByHand の 1 か所
- xSendVerdict の上限はサーバーが決め、全体の額そのものは返さない
- 見え方の名前・短縮リンクの仮の URL・書きかけの控え（localStorage）に、他人の情報や秘密は入らない
- 新しい画面に dangerouslySetInnerHTML・console.log・NEXT_PUBLIC の新しい秘密はない
