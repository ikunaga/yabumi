## 問題がなかった主な点

- 新しい表（ai_image_jobs・ai_image_notices・learning_term_reads・learning_tip_shows）は RLS が有効で、ポリシーは本人の select だけ、利用者への grant も select だけ。書き込みはサーバーか security definer の関数だけ
- notification_prefs で利用者が書ける列は、前からの列と learning_enabled だけ
- security definer の関数（connected_store_sources・学びの 4 本）は、revoke all（public・anon・authenticated・service_role）と authenticated への grant、search_path = ''、auth.uid() が null なら止める、がそろっている。他人と存在しないプロジェクトの返し方が同じで、存在を推測できない
- reserve_ai_images は上限を関数の中で固定し、全体で 1 本の advisory lock の中で数える。断った分は記録しない
- project_step_flags の置き換えで権限は広がっていない
- server action はすべてログインの情報から本人を取り、zod で形と長さを確かめ、projectId などは RLS の効くクライアントで確かめる。admin クライアントは owner で絞る
- Storage の AI の候補は `<本人のID>/gen/` だけ。他人のパスを指定できない
- 利用者の入力（topic・draft・direction_note・post）はタグで区切り、区切りのタグを崩している
- todoAction の行き先・?done=・用語集のリンクに open redirect はなく、dangerouslySetInnerHTML もない
- Gemini の鍵は見出しで送り、URL・ログ・NEXT_PUBLIC_ に出ていない
- 他人に情報を見せる経路は増えていない
