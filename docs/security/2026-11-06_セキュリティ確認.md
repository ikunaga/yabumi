## 問題がなかった主な点

- goals・goal_milestones・goal_kpis は RLS を有効にし、本人の select だけ。書けるのは security definer の関数だけで、状態・結果・閉じた日時・区切りの日付は関数が決める
- 書く関数はすべて auth.uid() が null なら断り、project・goal の持ち主を確かめる。search_path = ''、revoke all と authenticated への grant がそろう。中で使う関数は誰にも grant していない
- goal_metric_total は security invoker で、使う表はどれも本人の RLS
- 橋渡しのトリガーは AFTER で、RLS を通った行でだけ動き、他人の goal は作れない。ループしない
- quote_post_id は列の grant と check で X・数字だけに縛り、送信のジョブは引用を拾わない
- x_search_usage・reserve_x_search・reserve_ai_usage・reserve_ai_images は service_role だけが呼べ、上限は関数の中で固定、ロックの中で数え、断った分は記録しない
- 済んだ会話は書き換えられず、本人の delete は止めない
- server action と route handler は、どれも getClaims で本人を確かめ、zod か uuid で検証し、所有は RLS の効くクライアントで確かめる。admin は owner_id で絞る
- Claude を呼ぶところはすべて予約の入口を通る。Gemini・X の検索も予約を通る
- open redirect なし（戻り先は固定、名前は DB から、intent URL は encodeURIComponent）。dangerouslySetInnerHTML なし。X のアイコンは pbs.twimg.com の https だけ・no-referrer
- 貼られた投稿は区切ってから AI に渡し、「投稿に使わない」項目はネタ出し・相談・整える・画像の案に渡さない
- 鍵はサーバー専用のファイルだけで読み、ログに出さない
- 他人に情報を見せる経路は増えていない
